# UX Terminal — интерфейс для инвестора, не кванта

## Purpose / Scope

Пользователь уходит не с «что такое Sharpe?», а с «портфель здоров, вот 2 риска, вот
что проверить». Scope: структура подачи, язык, дизайн-система, доступность, статусы
данных. НЕ занимается: корректностью цифр (quant-honesty), процедурой проверки/выката (ship).

## When to invoke / When not

- Invoke: новый UI-блок, правка текстов/вёрстки, UX-линза совета для L1+.
- Not: чистые пайплайны без UI; правки скиллов/доков.

## Иерархия «ответ раньше данных» (decision process)

- **Level 1** — вывод за 20 секунд (Health-скор, вердикт словами). Всегда сверху раздела.
- **Level 2** — причины: 3–5 пунктов человеческим языком.
- **Level 3** — полные таблицы/графики, свёрнуты по умолчанию.
- Новый блок обязан назвать свой Level и место ДО реализации. Карточка = один вопрос;
  заголовок — вопрос пользователя («Дорого или дёшево?»), не термин.

## Mandatory checks (проверяемые)

- Плоский список одного раздела ≤7 модулей; новый модуль — только внутрь существующей
  группы (Обзор/Риск/Доходность/Действия/Данные), не в хвост списка.
- Один дисклеймер «не ИИР» на раздел (grep перед добавлением нового).
- Каждый квант-термин: человеческая подпись рядом или тултип без жаргона.
- Вердикты: число + слово («высокая/умеренная/низкая») + одно предложение «почему».
- Виджет с данными показывает as_of/статус (fresh/stale/fallback) — из site_status
  или meta файла; никаких技-сообщений в UI: пользователь видит «данные временно
  недоступны, показана версия от <даты>», а не stack trace/HTTP-код.
- Интерактивные элементы: достижимы с клавиатуры (button/tabindex), тач-цель ≥44×44px,
  контраст текста ≥ AA (использовать токены — они уже калиброваны).
- Цвет всегда дублируется словом (зелёный=хорошо, красный=риск, жёлтый=внимание).

## Дизайн-система (использовать, не изобретать)

Токены: `--surface --ink --ink-soft --ink-faint --line --accent-deep
--good/warn/risk/neut-fill/ink/bar --radius --shadow`. Паттерны: KPI-карточка (`pfxKpi`),
чипы, `details`-модули, скролл-таблицы `.*-table-scroll` с `col-sec` для мобайла,
мини-бары, skeleton `pfxShimmer`. Правило: grep существующего класса → потом новый CSS.

## Blocking conditions

Мёртвый CTA (кнопка без действия) · второй блок с тем же смыслом рядом · новый модуль
в плоский список >7 · термин без расшифровки в Level 1/2 · критичная инфа только цветом.

## Non-blocking warnings

Техническая метаинформация на премиальном месте экрана · англицизм там, где есть
русский эквивалент · Level 3 открыт по умолчанию.

## Anti-patterns (обобщённые уроки аудита)

Плоская простыня аккордеонов · дисклеймер-инфляция (предупреждение под каждым виджетом
= юридически и психологически ноль) · «coming soon» на витрине · два расчёта одного
смысла в соседних блоках без объяснения разницы.

## Output contract / DoD

До кода: Level + группа + заголовок-вопрос + вердикт-фраза. После кода: проверка по
ship (desktop/mobile/console — процедура там). DoD UX-части: все mandatory checks
пройдены, скриншот ключевого экрана снят.

## Interaction / Пример

Линза совета (L1+) → реализация → ship. Пример: «добавь Treynor» → не отдельный
аккордеон, а строка в существующей таблице risk-adjusted внутри группы «Риск», тултип
«доходность на единицу рыночного риска», вердикт-слово не нужен (Level 3).
