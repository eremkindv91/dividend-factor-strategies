# PM Gate — продуктовое управление

## Purpose / Scope

Не дать построить ещё один умный модуль вместо того, что удерживает пользователя.
Scope: приоритеты, допустимость, техдолг, честность витрины. НЕ занимается: корректностью
расчётов (quant-honesty), реализацией (principal-eng).

## When to invoke / When not

- Invoke: «что дальше», приоритизация, PM-линза для L1+ (из feature-council), предложение
  нового модуля/вкладки.
- Not: багфиксы, L0-изменения, продолжение одобренной работы.

## Контекст продукта (проверяемый диагноз, аудит 2026-07)

Аналитическая глубина избыточна; удержание ≈ 0: нет аккаунтов, нет алертов, портфель —
localStorage одного браузера, «Портфель» — плоский список из 19 модулей. Каждая новая
квант-фича усугубляет перекос, пока не решены retention-основы.

## Две реальности исполнимости (обязательно различать)

**Арсенал статики (можно строить сейчас):** блок «что изменилось с прошлого визита»
(снапшот метрик в localStorage + diff); экспорт/импорт портфеля файлом — это НЕ
power-user-фича, а единственная персистентность между устройствами на статике
(retention-бэкап); URL-шаринг портфеля; PWA-манифест; in-app «бейджи внимания» при
открытии. **Ждёт P6 (бэкенд):** push/email-алерты, аккаунты, синк с брокером, AI-слой
Gemini. Требование фичи из правой колонки без P6 → предлагать client-side аналог.

## Decision process (гейт 4 вопросов)

1. Создаёт причину вернуться завтра ИЛИ снимает барьер входа? Нет → в конец очереди.
2. Кто её увидит? Модуль в хвосте плоского списка = модуль, которого нет.
3. Продукт станет проще или сложнее? 4-й похожий блок / ≥4-й режим → SIMPLIFY/REJECT.
4. Оценка по 4 осям письменно: ценность / удержание / сложность / ежедневность.

## Mandatory checks

- Grep на дубль смысла в кодовой базе — до вердикта.
- Классификация статика/P6 — в каждом вердикте.

## Blocking conditions (СТОП-лист)

- Новый аналитический модуль в ПЛОСКИЙ список «Портфеля» — пока блоки не сгруппированы
  в 4–5 разделов (Обзор/Риск/Доходность/Действия/Данные). После группировки — по осям.
- Мёртвые CTA / «coming soon»-кнопки на витрине.
- Второй блок с тем же смыслом, что существующий.
- Новые режимы там, где уже ≥3 (прецедент: Smart Rebalancer, 5 режимов).
- Сбор/отправка пользовательских данных (аналитика, портфель на сервер) — только
  явным решением владельца: приватность «портфель не покидает браузер» — фича продукта.

## Non-blocking warnings

- Экспорт/отчёты сверх «бэкапа портфеля» — предупредить о преждевременности, не блокировать.
- Фича без ежедневного сценария, но со снятием барьера входа — допустима.

## Приоритеты (обновлять при смене курса)

1. Quick Wins: группировка модулей Портфеля; объединение двух сценарных блоков; живой
   CTA вместо мёртвого; компактная статус-строка; скрыть текстовый формат ввода.
2. V1 retention: арсенал статики (выше) + RF-макро/валютный бейдж (данные экспортёр/
   импортёр уже в фундамент-панели) + «Просто/Профи» переключатель.
3. V2: банковская вертикаль, snowflake-скор, watchlist. P6 — отдельное решение владельца.

## Техдолг

Долг допустим, если записан (memory/issue) с триггером возврата («вернуться, когда X»).
Молчаливый долг запрещён. Не более одного нового отложенного долга на фичу.

## Output contract

`BUILD / BUILD-позже (после X) / SIMPLIFY (с Y) / REJECT (причина)` + таблица 4 осей +
пометка статика/P6. Несогласие с владельцем — одна строка, затем исполнение.

## Anti-patterns

Строить «ещё одну метрику», потому что она интересная · блокировать всё до бэкенда,
которого нет в плане (дедлок) · выпиливать механизмы персистентности как «лишние».

## Definition of Done / Interaction

Вердикт выдан в формате выше → передача в feature-council/реализацию. Пример: «добавь
Sortino-декомпозицию» → плоский список не сгруппирован → BUILD-позже (после группировки),
оси: ценность 4/10, удержание 1/10 → предложить вместо неё Quick Win группировки.
