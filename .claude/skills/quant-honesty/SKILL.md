# Quant Honesty — доменная корректность

## Purpose / Scope

Ни одной выдуманной или методологически грязной цифры на сайте. Scope: данные, расчёты,
временная корректность, корпдействия, язык финансовых утверждений. НЕ занимается:
вёрсткой (ux-terminal), механикой CI (principal-eng/ship).

## When to invoke / When not

- Invoke: L2/L3 изменения; новая метрика/цифра в UI; правка пайплайна; правка порога;
  бэктест; отладка «числа не сходятся».
- Not: чистый UI без формул и данных (L0/L1 без новых цифр).

## Контракт метрики (required inputs каждой новой цифры)

Для каждой значимой цифры фиксируются: **source** (система-источник), **as_of** (дата
данных, не дата рендера), **coverage** (сколько тикеров/периодов реально покрыто),
**transformation** (как посчитано — формула/окно/частота), **class** — одно из:
`actual` (факт из источника) / `estimate` (модельная оценка, помечена) /
`derived` (вычислено из actual) / `fallback` (last-good, помечен). Нет какого-то
элемента → цифра не публикуется, вместо неё честное «н/д» с причиной.

## Временная корректность (mandatory checks для L3)

- **Point-in-time:** в расчёте на дату T участвуют только данные, доступные на T.
  Прогноз/отчёт года N не «знается» раньше публикации. Бэктест на ретроспективно
  исправленных данных — помечается как таковой.
- **Look-ahead:** запрещён; проверка — «мог ли инвестор знать это число в тот день?».
- **Survivorship:** делистинги не выбрасываются из истории (в панели есть `is_delisted`);
  универс бэктеста — состав на дату, не сегодняшний.
- **Календарь MOEX:** свежесть считается от последнего ТОРГОВОГО дня — выходной/праздник
  не делает данные «stale» (пороги вида 1.6 дня покрывают пт→пн; длинные праздники —
  проверять по календарю, не паниковать). Forward-fill цен через неторговые дни запрещён.
- **Частоты не смешивать:** дневные и месячные ряды соединяются только явной агрегацией
  (месячная точка = последний торговый день месяца). Дневной VaR из месячных данных —
  честное «недоступно», так уже сделано.
- Пропуск цены ≠ пропуск фундаментала: цена без сделок — н/д на дату; фундаментал —
  последний опубликованный отчёт с его as_of (это не forward-fill, это факт с датой).

## Корпоративные действия (общая политика, не список багов)

- Любая корректировка — только по официальному реестру (MOEX splits API) И порогу
  абсурдности, никогда «по всем подряд». До и после правки — счётчики охвата (сколько
  тикеров затронуто); отклонение от ожидаемого охвата = стоп. Прецеденты: TRNFP
  (over-adjust чуть не занулил 24 тикера), PLZL (дивспайк исключал бумагу из риска зря).
- Исключение бумаги из риск-метрик — только по неремонтируемому дефекту (ценовой разрыв),
  ремонтируемое (дивспайк) чинится без исключения.
- Смена тикера/редомициляция — через явный alias-маппинг (прецедент: TCSG→T), не догадки.
- Будущих дивидендных дат нет в реестре до объявления эмитентом — пустой календарь честен.

## Язык финансовых утверждений

Запрещено: «справедливая цена» как факт, «целевая цена», «купить/продать», «апсайд»,
«точка входа», «прогноз доходности». Замены: «модельная оценка», «дороже/дешевле
ROE-линии», «не прогноз», «требует проверки». Backfilled-портфель НИКОГДА не называть
историей реальных сделок. Каждая риск-метрика раскрывает частоту данных, окно и горизонт.
Дисклеймер «не ИИР» — один на раздел.

## Пороги (источник истины — код; здесь справочно)

`scripts/clean_portfolio_data.py`: DIV_YIELD_ABSURD=0.35, DIV_MONTH_ABSURD=0.50,
SERIES_JUMP=2.5 · `scripts/smartlab_reconcile.py`: TOL=0.07, CB=5; политика — пустой
НОВЫЙ год дозаливается flagged, история не перезаписывается · риск: ≥12 мес истории,
bootstrap ≥18 · банки: зоны 11/13/15% — аналитические. Расхождение skill↔код → код прав,
обнови skill. Изменение порога = L3-решение с обоснованием в коммите.

## Blocking conditions

Метрика без полного контракта · look-ahead в бэктесте · смешение частот без агрегации ·
корректировка корпдействия без реестра+порога+счётчиков · запрещённая лексика в UI.

## Non-blocking warnings

Coverage <80% универса — публиковать с явной пометкой охвата · derived-метрика на
estimate-входах — помечать класс худшего входа.

## Output contract / DoD

В вердикте/PR: источники, классы данных, что честно НЕ считаем и почему. Новый
JSON-контракт → валидатор (`scripts/validate_*.py`) + pytest в `tests/` в том же коммите.
Прогон затронутых тестов: `pytest tests/test_<область>* -q`.

## Interaction / Пример

Вызывается feature-council на L2/L3; реализация — по principal-eng; выкат — ship.
Пример: «покажи P/E по свежей прибыли» → контракт: source=SmartLab reconcile,
as_of=fiscal_year, class=actual, coverage 217/268 → в UI с датой года и пометкой
охвата; 28 тикеров без 2025 — «н/д», не экстраполяция.
