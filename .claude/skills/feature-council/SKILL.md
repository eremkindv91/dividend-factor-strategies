# Feature Council — совет из четырёх ролей

Любая заметная фича проходит совет ДО кода. Прочитай (Read) все четыре skill-файла этого
проекта и вынеси решение по каждой линзе. Это 5–10 минут, которые экономят день переделок.

## Процедура

1. **PM Gate** (`.claude/skills/pm-gate/SKILL.md`) — стоит ли строить: 4 вопроса гейта,
   СТОП-лист, оценка по 4 осям. Если REJECT/SIMPLIFY — сказать пользователю сразу,
   с альтернативой; строить только после его подтверждения.
2. **Quant Honesty** (`.claude/skills/quant-honesty/SKILL.md`) — есть ли реальные данные
   и честная математика: источник+дата, нет выдуманных значений, запрещённая лексика,
   существующие пороги. Если данных нет — фича меняется на «честное н/д» или отклоняется.
3. **UX Terminal** (`.claude/skills/ux-terminal/SKILL.md`) — где фича живёт в иерархии
   (Level 1/2/3), заголовок-вопрос, человеческий вердикт, один дисклеймер, мобайл-план.
4. **Principal Eng** (`.claude/skills/principal-eng/SKILL.md`) — как встроить: какие
   существующие функции расширяем (grep дублей ОБЯЗАТЕЛЕН), гочи, план проверки и деплоя.

## Формат вывода совета (перед кодом)

```
Вердикт: BUILD / BUILD-позже / SIMPLIFY / REJECT
PM:    ценность X · удержание X · сложность X · ежедневность X; [замечание]
Quant: источник данных = …; ограничения = …; чего честно НЕ считаем = …
UX:    место = [раздел/уровень]; заголовок = «…»; вердикт-фраза = «…»
Eng:   расширяем [функции/файлы]; риски = …; DoD = preview+mobile+deploy+live
```

После совета — реализация строго по Definition of Done из principal-eng
(preview → commit → deploy → live-проверка). Один этап за проход; следующий — после
подтверждения, что сайт цел.

## Пограничные случаи

- Багфикс данных/вёрстки — совет не нужен, но quant-honesty и principal-eng линзы
  применяются по ходу.
- Пользователь явно сказал «просто сделай X» после озвученного несогласия — исполнять,
  зафиксировав позицию одной строкой, без повторных споров.
