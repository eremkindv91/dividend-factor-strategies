# Двухконтурная «Пила» рынка: MCFTR и IMOEX

Модуль «Помощник фазы рынка» показывает, где рынок находится относительно последнего
значимого экстремума — по ДВУМ индексам, которые отвечают на разные вопросы.

**Простыми словами:** MCFTR отвечает на вопрос, как изменилась полная стоимость вложений в
российский рынок с учётом дивидендов. IMOEX показывает только ценовое движение и используется
для отдельной ценовой swing/zigzag-логики.

## Почему два контура

- **MCFTR (полная доходность) — основной инвестиционный режим.** Индекс полной доходности
  МосБиржи учитывает дивиденды, поэтому отражает реальное движение капитала инвестора и не
  создаёт ложных «дивидендных гэпов». Порог разворота 9.5%. Это индикатор фазы, не прогноз.
- **IMOEX (ценовой индекс) — дополнительный ценовой контур.** Публичная воспроизводимая
  реализация swing/zigzag-подхода по ЦЕНОВОМУ индексу: порог разворота 7%, зона покупки −13%
  от последнего подтверждённого максимума, зона фиксации +17% от последнего подтверждённого
  минимума. Ценовой индекс НЕ учитывает дивиденды.

## Почему параметры нельзя смешивать

Уровни IMOEX (−13%/+17%, порог 7%) применяются ТОЛЬКО к IMOEX; зоны MCFTR (9.5%, реджимы
investment_regime) — ТОЛЬКО к MCFTR. Экстремумы одного индекса никогда не используются как
anchor другого; исторические волны и вероятности не объединяются. Единый источник параметров —
`market_saw/production/config.py` (`INDEX_CONFIGS`).

## Формулы IMOEX

```
buy_level = last_confirmed_high · (1 − 0.13)      # уровень покупки
fix_level = last_confirmed_low  · (1 + 0.17)      # уровень фиксации
zone = buy   если price ≤ buy_level
     = fix   если price ≥ fix_level
     = neutral иначе
move_from_high_pct = price / high − 1             # <0 при просадке от максимума
move_from_low_pct  = price / low  − 1             # >0 при росте от минимума
distance_to_buy_pct = price / buy_level − 1
distance_to_fix_pct = price / fix_level − 1
```

**Перекрытие зон:** при широком диапазоне (high/low > ~1.345) `buy_level > fix_level`, и зоны
перекрываются в `[fix_level, buy_level]` — цена там одновременно ≥13% ниже максимума И ≥17%
выше минимума (рынок пилило). Перекрытие разрешается детерминированно в пользу `buy`
(консервативно для докупки на просадке). Настоящая neutral-зона есть только при узком диапазоне.

## Anti-look-ahead

Локальный максимум подтверждается ЛИШЬ после падения от него на ≥ порога; минимум — лишь
после отскока на ≥ порога. До подтверждения экстремум — кандидат. Текущая незавершённая волна
НЕ входит в массив завершённых волн. Расчёт воспроизводим при последовательном добавлении
данных по одному торговому дню (`market_saw/tests/test_zigzag_engine.py`). Общий движок
`zigzag_engine.run_zigzag` доказан бит-идентичным канонической MCFTR-реализации.

## Official close ≠ live snapshot

- **official_close** — цена последней ЗАВЕРШЁННОЙ торговой сессии MOEX. ТОЛЬКО она подтверждает
  экстремумы, завершает волны, влияет на survival-распределение.
- **live_snapshot** — внутридневная котировка (MOEX ISS marketdata). Используется ТОЛЬКО для
  текущей позиции маркера «сейчас», текущей зоны и расстояний до уровней. НИКОГДА не подтверждает
  максимум/минимум, не завершает волну, не переписывает официальный CLOSE.

Фронт подтягивает live snapshot напрямую из ISS при открытии блока / переключении на IMOEX /
возврате вкладки (троттлинг 60 c, AbortController + timeout, без постоянных таймеров). Ошибка
ISS не показывается пользователю — остаётся официальный snapshot.

## Источники MOEX ISS

- История (закрытые сессии): `/iss/history/engines/stock/markets/index/boards/{board}/securities/{secid}.json`,
  колонки TRADEDATE, CLOSE, пагинация start=0,100,…
- Live snapshot: `/iss/engines/stock/markets/index/boards/{board}/securities/{secid}.json?iss.only=marketdata`,
  колонки CURRENTVALUE (текущее значение сессии), LASTVALUE (предыдущий официальный CLOSE), SYSTIME.
- Доски: MCFTR → **RTSI** (engine=stock, market=index), IMOEX → **SNDX**. `discover_index_board`
  уточняет primary-доску, при сбое — fallback из `INDEX_CONFIGS`.

## Fallback и свежесть

Каждый контур обновляется независимо (`market_saw/production/build_marketsaw.py` для MCFTR,
`build_imoex_saw.py` для IMOEX). При сбое ISS билдер НЕ перезаписывает файл пустым — остаётся
предыдущий валидный (last-good, атомарная запись). Сбой одного контура не роняет другой;
`marketsaw_manifest.json` честно отражает `available`/`fallback` по каждому индексу. Свежесть
считается по торговому календарю MOEX (`scripts/trading_calendar.py`): выходной/праздник не
делает данные устаревшими; штатный лаг официального индекса — до одной завершённой сессии.

Разделяются: `source_as_of` (дата рыночных данных) ≠ `generated_at` (время пересборки файла) ≠
`last_success_at` (последнее успешное получение). Свежесть НИКОГДА не определяется по одному
`generated_at`.

гарантия против стирания orphan-republish).

## Диагностика

- Пусто/устарело в UI: сначала логи последнего `market-saw-update.yml`, затем `marketsaw_manifest.json`
  (`available`/`fallback`/`freshness_status` по индексу), только потом код. Выходной ≠ инцидент.
- `python market_saw/shared/moex_index_fetch.py IMOEX` — проверить доску, последнюю дату, snapshot.
- `python market_saw/production/build_imoex_saw.py /tmp/x.json` — локальная сборка IMOEX.
- Тесты: `python3 -m pytest market_saw/tests/ -q`.

## Ограничения

- IMOEX — ценовой индекс, не учитывает дивиденды (для полной картины — MCFTR).
- Не бренд и не точная копия закрытой методики — публичная воспроизводимая реализация
  swing/zigzag-подхода. Не сигнал, не прогноз, не индивидуальная инвестиционная рекомендация.
