## 3. Текущие формулы (что реально считается)

Всё в Python, `value_bank()`. В JavaScript считаются только производные от ползунка COE.

| Показатель | Формула | Знаменатель |
|---|---|---|
| `p_bv` | `mcap / (капитал Ф.123 × 1000)` | **регуляторный** капитал |
| `p_e` | `mcap / (прибыль Ф.102 TTM × 1000)` | прибыль **РСБУ соло** |
| `roe` | `100 × прибыль Ф.102 TTM / средний капитал Ф.123` | регуляторный капитал |
| `payout` | `100 × (див. TTM × число акций) / прибыль Ф.102` | прибыль соло |
| `n10_headroom` | `Н1.0 − регуляторный минимум` | — |
| `dividend_capacity_score` | эвристика 0–100 из headroom, ROE, payout, Н1.1 | — |
| `data_quality_score` | 100 − штрафы за отсутствующие vintage и разрыв периметра | — |
| ROE-линия (JS) | `P/капитал ЦБ ≈ ROE / COE`, COE — **ползунок**, единый для всех | — |

Капитализация считается как обычка + префы (`SBERP`, `BSPBP`).

## 4. Точки смешения периметров

Главное, что нужно понимать: **числитель и знаменатель во всех мультипликаторах — из разных
юридических лиц.** Капитализация — публичного эмитента (группы), капитал и прибыль — отдельного
банка по РСБУ.

| Что | Периметр |
|---|---|
| `mcap`, `price`, дивиденды | публичный эмитент / группа (MOEX) |
| капитал Ф.123 | банковское юрлицо, Базель III, **включая суборды** |
| прибыль Ф.102 | банковское юрлицо, РСБУ |
| число акций | публичный эмитент |

Разрыв объявлен в конфиге полем `ifrs_gap`: `material` у VTBR, T, DOMRF; `moderate` у SBER,
SVCB, MBNK; `low` у BSPB. Он попадает в предупреждения и снижает `data_quality_score`.

**Существенно в пользу текущей реализации:** вкладка уже **не** выдаёт это за справедливую
стоимость. В коде и в интерфейсе прямым текстом:

> «Это не бухгалтерский капитал по МСФО и не IFRS P/BV. Коэффициент ниже 1 сам по себе не
> доказывает недооценку.»
> «Линия P/капитал ЦБ ≈ ROE / COE — диагностический ориентир внутри сектора, а не fair value
> или целевая цена.»

Показатель назван `P/капитал ЦБ`, а не `P/BV` — то есть требование спеки §2.1 **уже выполнено**.
Ключ `p_bv` в JSON оставлен для обратной совместимости, и это задокументировано в шапке модуля.

Поэтому задача не «убрать обман», а **добавить второй, полноценный контур оценки** — и не сломать
работающий регуляторный.

Нарушения запретов §31, которые реально есть сейчас:
- **единый COE для всех банков** без individual adjustment (ползунок) — §31;
- **капитализация последнего ROE навечно** в линии `ROE/COE` — §31;
- поля `perimeter_note`, `valuation_allowed`, `perimeter_match` в коде читаются, но **в конфиге
  отсутствуют** — периметр описан лишь грубым `ifrs_gap`.

## 5. Выполнимость Residual Income: что есть и чего нет

Проверено по фактическим данным, не по предположениям.

### Есть

| Вход RIM | Источник | Покрытие |
|---|---|---|
| **Капитал (book value)** | `site/site_financials.json` → `total_equity` | SBER/VTBR/T/BSPB 2011–2025, DOMRF 2021–2025, SVCB 2020–2024, MBNK 2014–2024 |
| Чистая прибыль | там же, `net_income` | все 7, до 2025 |
| ROE исторический | там же, `roe` | все 7 |
| Дивиденды | там же + MOEX ISS | SBER/BSPB/T/SVCB/MBNK; **у DOMRF поля нет** |
| EPS | там же | SBER/VTBR/BSPB с 2011; T/SVCB/MBNK только 2024–2025 |
| Число акций, казначейские | MOEX ISS `issue_size` | все |
| Цена, капитализация | MOEX ISS | все |
| Безрисковая ставка | G-кривая КБД MOEX (`site/bonds/chart_data.json`, 11 точек) | есть |
| Ключевая ставка ЦБ | `site/macro_cbr.json` | 14,0% |
| **Beta** | `site/returns.json`, месячные ряды | SBER/VTBR/BSPB 91 набл., T 81, SVCB 31, MBNK 27, **DOMRF 0** |
| Регуляторный overlay | формы 102/123/135 | все 7 |

### Нет

1. **Балансовый капитал — из SmartLab, а не из отчётности.** У всех 7 банков
   `source_status: smartlab_fallback`, `source_url: smart-lab.ru`. По §4.2 это вторичный
   источник: агрегатор без ссылки на первичный документ. По §4.3 его можно применять только
   с признаком `secondary_fallback`, предупреждением в интерфейсе и **запретом публиковать
   полную справедливую стоимость**.
2. **Нет разделения «капитал акционеров материнской компании» vs `total_equity`.** SmartLab даёт
   один агрегат. Для VTBR (существенные неконтролирующие доли и «вечные» субординированные
   инструменты) это может искажать базу RIM на десятки процентов.
3. **Нет прибыли, доступной владельцам обыкновенных акций.** У VTBR это критично: префы
   двух типов у государства, дивиденд по ним не равен дивиденду по обычке. Текущий код прямо
   допускает: `pref dividend assumed equal to ordinary`.
4. **Нет BV на акцию** ни у одного банка (поля нет).
5. **Нет рыночного индекса в `returns.json`** (`IMOEX`/`MCFTR` отсутствуют в `data`) — для беты
   нужен бенчмарк; он есть отдельно в `market_history.json` / `marketsaw`, нужно связать.
6. **Нет истории по DOMRF** для беты и нет дивидендов → RIM для него будет `unavailable`.
7. **Нет казначейских акций и корпоративных действий** как отдельного слоя (сплиты MOEX есть,
   байбэки — нет).
8. МСФО-сид `data/market_pe_ifrs_seed.json` — только **чистая прибыль FY2025**, 12 тикеров,
   источники — СМИ (Ведомости, bosfera). Как база капитала не годится.

### Вывод по выполнимости

Residual Income **считается на существующих данных для 6 из 7 банков**, но с обязательным
статусом `limited` по §14.2 — потому что база капитала вторична (SmartLab), а не из отчётности.
DOMRF → `unavailable`. Публиковать полную справедливую цену акции без первичных МСФО-данных
спека запрещает (§4.3), и это правильно: ошибка в базе капитала входит в fair value линейно.

## 6. Что сохранить, переименовать, заменить

**Сохранить без изменений:**
- весь контур ЦБ: формы 102/123/135, `n10/n11/n12`, headroom, история, `validate_cbr_data.py`;
- проверку `ticker ↔ regnum` по имени из ЦБ (падает громко — это ценно);
- приведение дивидендов к текущей базе акций после сплитов;
- честные предупреждения и `data_quality_score`;
- `p_bv` как ключ JSON (обратная совместимость, §28).

**Переименовать:** ничего критичного — `P/капитал ЦБ` уже корректен. Стоит добавить
`p_regcap` как явный алиас и объявить `p_bv` устаревшим в схеме.

**Заменить/добавить:**
- `banks_config.json` → полный блок периметра (`perimeter_match`, `valuation_allowed`, …);
- COE: с единого ползунка на CAPM по каждому банку (бета из `returns.json`, RFR из G-кривой)
  + ползунок как сценарный оверрайд, а не как единственный источник;
- новый модуль RIM + прогноз + terminal value;
- `valuation_v2.json` рядом с `valuation.json` (не вместо — §28).

## 8. Перечень тестов к реализации (§21)

Математика: RI = 0 при ROE = COE; fair P/BV = 1 при ROE = COE; монотонность по ROE и по COE;
terminal growth < COE; отрицательный капитал → `unavailable`; отсутствие NaN/Infinity.
Капитал и акции: clean surplus (капитал₍t₎ = капитал₍t−1₎ + прибыль − дивиденды); сплиты.
Периметр: запрет подстановки Ф.102/Ф.123 в базу оценки; `material_mismatch` → не `full`.
COE: индивидуальность по банкам; отказ при отсутствии беты.
Контракт: схема JSON, отсутствие silent fallback, регрессия текущей вкладки.

## Открытый вопрос к владельцу

Спека требует первичную отчётность МСФО (§4.1) и запрещает выдавать оценку за полную без неё.
Автозагрузки отчётности в проекте нет и создать её из открытых источников надёжно нельзя —
эмитенты публикуют PDF/XLSX без единого формата.

Варианты:
- **A.** Считать RIM на SmartLab-капитале со статусом `limited`, без публикации целевой цены —
  показывать справедливый P/BV и знак создания стоимости. Работает сразу, честно, но неполно.
- **B.** Сначала сделать контролируемый импорт `data/banks/ifrs/<ticker>/<date>.json` с ручной
  сверкой по официальным релизам (как уже сделано для `market_pe_ifrs_seed.json`), затем RIM
  со статусом `full`. Дольше, требует ручного ввода, зато соответствует §4.1.
