# CLAUDE.md — dividend-factor-strategies

Инвестиционный дашборд рынка РФ (статика: `site/index.html` + `site/app.js` + `site/styles.css`,
vanilla JS, GitHub Pages). Данные генерирует CI (Python-пайплайны в `scripts/`, `market_saw/` и др.),
публикация на ветку `gh-pages`. Основная рабочая ветка — `dividend-site`.

## Редизайн (активный workstream)

Полная спека редизайна: [`docs/redesign/SPEC.md`](docs/redesign/SPEC.md).
Как поднять локально, снапшот данных, регрессия: [`docs/redesign/RUNBOOK.md`](docs/redesign/RUNBOOK.md).

Правила (из спеки):
- **Одна итерация за сессию**, отдельная ветка `redesign/<этап>` от `dividend-site`, один коммит.
- **Расчётный слой не переписывать** — задача упаковать и честно подать существующую математику.
  Перед любыми правками: `node tools/regression.js --mode=check` (0 расхождений — обязательно).
- **Ни одно число не должно вводить в заблуждение**: горизонт, база (gross/net), надёжность выборки,
  дата данных — рядом с каждой метрикой.
- Данные CI-генерируемые (`site/data.json`, `returns.json` и др.) в `.gitignore` — локально берутся
  снапшотом с Pages (`site/_snapshot/`, не коммитить).

## Инварианты honesty (общий принцип проекта)

- Только реальные данные, без выдуманных значений; при отсутствии поля — честное «н/д» / graceful
  degradation, а не оценка. Не публиковать число, не прошедшее контракт качества (пример:
  `scripts/build_market_pe.py` — агрегированный P/E гейтится до валидации фундамент-слоя).
- Портфель пользователя считается локально в браузере и не покидает его.
- Не ИИР (не индивидуальная инвестиционная рекомендация) — на месте, где показываются оценки.
