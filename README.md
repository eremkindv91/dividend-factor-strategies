## О чём работа

Работа исследует два вопроса: насколько хорошо классические факторные стратегии работают на российском и японском рынках, и можно ли предсказать дивидендную политику компаний с помощью машинного обучения. Россия и Япония выбраны потому, что это два очень разных рынка — по доле плательщиков дивидендов, структуре инвесторов и макроэкономическому режиму.

Исследование состоит из трёх частей:
1. **Бэктест факторных стратегий** — тестирование портфелей на основе факторов Fama–French (Value, Momentum, Quality, Size, Investment) на обоих рынках за 2011–2025 гг.
2. **Декомпозиция фактора Quality** — какие именно показатели качества (ROE, маржинальность, долговая нагрузка) работают на каждом рынке
3. **ML-прогнозирование дивидендов** — сравнение пяти моделей (CatBoost, XGBoost, LightGBM, Random Forest, логистическая регрессия) с линейной моделью Фамы–Макбета

### Основные результаты

- На российском рынке 4 признака дивидендной истории объясняют 99,6% предсказательной силы модели из 146 признаков — дивиденды предсказывают дивиденды
- Преимущество ML над линейной моделью проявляется только на японском рынке (+6,6 п.п. ROC-AUC), на российском разница нулевая
- Состав значимых дескрипторов Quality существенно различается между рынками

### Гипотезы

- **Г1:** Эффективность факторных стратегий различается между рынками РФ и Японии
- **Г2:** Фактор Quality имеет разное наполнение на разных рынках
- **Г3:** Преимущество ML зависит от структуры рынка (доли плательщиков)
- **Г4:** Вклад дивидендной истории различается между рынками

### 05. Статистическая валидация результатов

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/eremkindv91/dividend-factor-strategies/blob/main/notebooks/05_statistical_validation.ipynb)

Формальная проверка результатов бэктеста (ноутбуки 01–02): значимость превышения коэффициента Шарпа над индексом, надёжность оценок на ~160 месячных наблюдениях, поправка на множественное тестирование при отборе дескрипторов. Методы:
- **Качество данных** — Jarque–Bera (нормальность), Ljung–Box на квадратах (кластеризация волатильности), ADF + KPSS (стационарность)
- **Значимость Sharpe** — тест Jobson–Korkie с поправкой Memmel (2003) и робастный Ledoit–Wolf (2008, HAC)
- **Block bootstrap** — circular block bootstrap (5000×, блок 6 мес.): 95%-доверительные интервалы Sharpe/CAGR и bootstrap p-value
- **Множественное тестирование** — пороги Harvey–Liu–Zhu (2016, |t|>3.0) и процедура Benjamini–Hochberg (FDR 10%)

Итог: на японском рынке индекс значимо обыгрывает только profitability-Quality (LW p≈0.04, bootstrap p≈0.02); на российском различия Sharpe статистически незначимы; из 53 IC-дескрипторов строгие поправки переживает единственный — FCF yield.

### Финальные панели для ML

В папке `data/panels_final/` лежат обработанные панели, которые подаются на вход ML-моделям.

#### `panel_russia_final.csv`
- **Размер:** 3 048 наблюдений × 208 признаков
- **Период:** 2011–2025 (15 лет)
- **Компании:** 268 российских эмитентов
- **Пропуски:** 32% (структурные — отраслевая специфика)
- **Обработка:**
  - Исключены признаки с заполненностью < 2%
  - Для CatBoost и LightGBM пропуски сохранены нативно (`nan_mode='Min'`)
  - Для XGBoost, Random Forest и логистической регрессии — медианная импутация по обучающему окну (функция `_fill_numeric()`, без утечки из будущих периодов)
  - Переменные взаимодействия отсечены: ROE в диапазоне (−100%, 200%), долг/EBITDA в (−10, 30)

#### `panel_japan_final.csv`
- **Размер:** 3 660 наблюдений × 155 признаков
- **Период:** 2010–2025 (16 лет)
- **Компании:** 246 японских эмитентов (Nikkei 225 + расширение)
- **Пропуски:** 19% (ниже, чем в России — лучшая информационная полнота японского рынка)
- **Обработка:** идентична российской панели

#### Как панели используются в коде

1. **Загрузка:** `pd.read_csv('data/panels_final/panel_*_final.csv')`
2. **Walk-forward CV:** расширяющееся окно, train ≤ t−1, test = t, начиная с 2016 года
3. **Целевые переменные:** `paid_next` (факт выплаты, бинарная классификация) и `dps_next` (размер дивидендов, регрессия)
4. **Отбор признаков:** автоматический по feature importance после первого прохода
5. **Аблация (4 набора):**
   - А — все 146/131 признаков
   - Б — без дивидендной истории (142/127)
   - В — дивидендная история + категориальные (6/5)
   - Г — только дивидендная история (4/3)
6. **Модели:** CatBoost (1200 итераций), XGBoost (800), LightGBM (800), Random Forest (400 деревьев), логистическая регрессия
7. **Калибровка:** изотоническая регрессия на OOF-предсказаниях

## Банки РФ / данные ЦБ РФ (вкладка «Банки РФ»)

Вкладка показывает официальную отчётность банков из Банка России (только реальные значения, без синтетики).

**Источник:** веб-сервис ЦБ РФ `CreditOrgInfo.asmx` (`RegNumToIntCode`, `Data102F`) — **форма 102** «Отчёт о финансовых результатах». Каждое значение трассируется до символа Ф.102 (`symbol`), формы и `source`.

**Как обновляется:** GitHub Actions `update-cbr-banks.yml` — ежедневно (03:00 UTC ≈ 06:00 МСК) + вручную (workflow_dispatch). Отчётность ЦБ **квартальная** (не ежедневная): пайплайн ежедневно проверяет данные, и если новых нет — JSON не меняется и коммита нет (workflow success). При недоступности ЦБ прошлая версия остаётся.

**Метрики (все коды подтверждены на реальных ответах ЦБ):**
- **Ф.102** (фактически публикуется помесячно): чистая прибыль (символ 61101), прибыль до налога (01000) — тыс. руб., накопленным итогом; режим «За период» = расчётная разность соседних накопленных значений (`calculated_from_official`).
- **Ф.123** (месячная): капитал итого (код 000), базовый (102), дополнительный (203) — тыс. руб. на дату.
- **Ф.135** (месячная): нормативы Н1.0/Н1.1/Н1.2/Н2/Н3/Н4 — %.
Отчётные даты — реальные доступные из `GetDatesForF102/123/135` (не перебор вслепую).

**Честно недоступно (см. `unavailable` в metric_mapping.json):** «активы» из Ф.101 (сумма счетов 1-го порядка ≠ публикуемым активам ф.0409806 — формула перегруппировки не валидирована); «процентные/комиссионные доходы» (итог Части 1 Ф.102 включает корректировки и восстановление резервов — подписывать его «процентными доходами» некорректно).

**Ручной запуск:**
```
python3 scripts/cbr_banks/build_cbr_banks.py     # собрать site/cbr/*.json из ЦБ
python3 scripts/cbr_banks/validate_cbr_data.py   # проверить (трассируемость, нет синтетики)
python3 scripts/cbr_banks/cbr_soap.py 1481 2026-04-01   # проверить один банк
```

**Статусы качества данных:** `official_direct` — символ подтверждён в реальном ответе ЦБ; `missing` — данных нет (не публикуем как число); `calculated` — рассчитано из официальных (пока не используется).

**Ограничения:** реестр v1 — точечный (12 системно значимых банков по рег.номерам; названия и данные из ЦБ, полный список КО — стадия 2); значения накопленным итогом (не «чистый квартал»); форма 135 (нормативы) в SOAP-сервисе напрямую не найдена. Не ИИР.

## MOEX Bond Finder (вкладка «Облигации» → Bond Finder)

Месячный шорт-лист привлекательных рублёвых облигаций + предложение аллокации целыми лотами.
**Это кандидаты для ручной проверки, не сигналы** — фиксированный дисклеймер выводится всегда.

**Рейтинги:** действующие рейтинги выпусков ежедневно загружаются из официальных публикаций АКРА,
«Эксперт РА» и НКР и связываются строго по ISIN. В JSON сохраняются агентство, дата действия и
ссылка на карточку выпуска. Если агентств несколько, для фильтра и скора берётся минимальный рейтинг;
issuer-name mapping не используется. При временном сбое разрешён last-good cache не старше 14 дней,
а при недоступности всех источников новый JSON не публикуется. Налог 13% — приближение для ранжирования,
не налоговый калькулятор; ревью журнала — приблизительный
total return (изменение грязной цены + линейное начисление купона); исторический бэктест as-of дат
пока не реализован (стадия 2).

**Как это работает:** два прохода — дешёвый префильтр всех торгуемых бордов (динамическое обнаружение,
рублёвые, без оферт/коллов, положительный сырой G-спред, стратифицированный отбор топ-60 с квотами
качественным бумагам) → дорогое обогащение (bondization: фикс-купон/без амортизации; description:
ПИР `HIGHRISK`, квал-флаг, ИНН; история 130 сессий: медианный объём 20 сессий, перцентиль спреда по
собственной истории ISS ZSPREAD). Скор = 1.0·z(G-спред в дюрационной корзине 0-1/1-2/2-3/3-5/5+) +
0.4·риск-прокси + 0.3·z(log медианного объёма) + 0.3·бонус за спред ≥80-го перцентиля +
0.5·z(официального рейтинга выпуска). Профили
(консервативный/сбалансированный/агрессивный) и веса — в `bonds/finder_config.json`.

**Валидационный цикл:** каждый прогон пишет журнал (`data/bond_finder/journal.json`, коммитится) и
на следующих прогонах сравнивает прошлые списки с RUCBTRNS («Проверка себя» на вкладке). События
(новые размещения, спред у 90-го перцентиля) — лента «События» по diff вселенной день-к-дню.

**Ежемесячное использование (3 команды):**
```
python3 bonds/bond_finder.py                      # собрать шорт-лист (≈220 запросов ISS)
python3 scripts/validate_site_data.py bonds       # проверить контракты
python3 -m http.server 8777 --directory site      # открыть http://localhost:8777/#bonds
```
В проде всё это делает ежедневный `bonds_update.yml` автоматически. Схема ISS и все проверенные
поля/расхождения — `docs/ISS_SCHEMA_NOTES.md`.

## Банки РФ — секторная оценка (вкладка «Банки РФ» → Оценка сектора)

Секторный one-pager по публичным банкам MOEX: P/BV, ROE, P/E, пэйаут, дивдоходность, Н1.0 +
scatter ROE×P/BV со справедливой линией `P/BV = ROE / COE` (слайдер COE 12–30%, дефолт 20%).
Не ИИР.

**Источники (все реальные, каждая цифра со своей датой):**
- **MOEX ISS** — капитализация (`marketdata.ISSUECAPITALIZATION`, обычка + префы; fallback
  `цена × ISSUESIZE`) и реально выплаченные дивиденды (`/iss/securities/{secid}/dividends.json`
  → TTM дивиденд/акцию, доходность, пэйаут).
- **ЦБ РФ (SOAP, переиспользует `cbr_soap.py`)** — капитал (Ф.123 код 000), прибыль TTM
  (Ф.102, скользящие 4 квартала из накопленных значений), Н1.0 (Ф.135).

**Ticker↔regnum** проверяется на каждом прогоне против названий ЦБ (при несовпадении — warning
в строке банка, банк не выпадает): SBER→1481, VTBR→1000, T→2673, SVCB→963, BSPB→436, MBNK→2268.
Конфиг — `scripts/cbr_banks/banks_config.json` (JSON, не YAML: workflow stdlib-only).

**Честные ограничения (per-cell warnings, не сноски):**
- **РСБУ соло ≠ МСФО группы** — существенно для ВТБ и Т-Технологий (широкий небанковский периметр),
  умеренно для Сбера. Виден кейс ВТБ: ROE РСБУ 22%, но P/BV 0.40 — рынок оценивает по МСФО.
- **Капитал Ф.123 — регуляторный** (Базель III, с субордами), не бухгалтерский equity → P/BV
  смещён вниз (Сбер ~0.8 против ~1.0 к МСФО-капиталу). Задокументировано, не «поправлено» молча.
- Пэйаут приближённый (дивиденд префов принят равным обычке; прибыль РСБУ соло).
- DOM.RF акциями не листингован (только облигации) → в оценке нет.

**Прогноз (опционально):** `data/bond_finder/…` — нет; для банков `data/cbr_banks/forecasts.json`
(ручной ввод profit/ROE/payout по годам); при отсутствии — прогнозные поля не рендерятся.

**Обновление:** `update-cbr-banks.yml` (ежедневно; отчётность ЦБ месячная, цены MOEX ежедневно).
Ручной запуск: `python3 scripts/cbr_banks/build_banks_valuation.py`; тесты
`python3 scripts/cbr_banks/test_banks_valuation.py`.

## Дивидендный календарь РФ

`python scripts/build_dividend_calendar.py` собирает `site/dividend_calendar.json` из официального
MOEX ISS, используя один bulk-запрос цен и ограниченный параллельный сбор дивидендов. Общий модуль
`scripts/dividend_calendar_core.py` отвечает за stable ID, дедупликацию, T+1 по торговому календарю,
статусы lifecycle, provenance и legal payment deadlines. `scripts/update_events_calendar.py` проецирует
тот же payload в обратно совместимый короткий календарь событий, не запрашивая MOEX второй раз.

`market_confirmed` означает подтверждение суммы и даты реестра в MOEX ISS, но не отдельную проверку
решения собрания акционеров. SmartLab используется только как discovery для короткого блока и не
становится actionable-событием. Точная дата выплаты не рассчитывается: без explicit source показывается
только крайний срок. Портфельный cash-flow считается локально в браузере и не входит в статический JSON.

P1-обогащение остаётся opt-in: при наличии `TINVEST_TOKEN` календарь сопоставляет уже найденные
MOEX-события с ответами T-Invest и может добавить explicit `last_buy_date`, `payment_date` или
отмену. Токен не попадает в JSON и логи. `shareholders_approved` создаётся только из строк
`data/dividend_disclosure_decisions.csv` с `review_status=verified`: для них обязательны источник
из доверенного реестра эмитента/e-disclosure, дата решения, сумма и дата реестра. Команда
`python scripts/discover_dividend_disclosures.py --network` формирует только очередь кандидатов
для ручной проверки и не меняет public calendar.

```bash
python scripts/build_dividend_calendar.py
python scripts/validate_dividend_calendar.py
python scripts/update_events_calendar.py
python scripts/validate_events_calendar.py
python scripts/discover_dividend_disclosures.py --network --limit 30
```

Ежедневный lightweight workflow `.github/workflows/dividend_calendar.yml` публикует оба JSON аддитивно;
при ошибке validation текущий `gh-pages` остаётся без изменений.
